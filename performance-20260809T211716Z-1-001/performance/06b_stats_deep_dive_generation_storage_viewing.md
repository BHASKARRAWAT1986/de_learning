# Statistics Deep Dive — Generation, Storage & How to View Them

---

## Overview: Three Levels of Statistics

```
┌─────────────────────────────────────────────────────────────────────┐
│  Level 1: FILE-LEVEL STATS                                          │
│    → min/max/nullCount per column per Parquet file                  │
│    → Stored in: Delta Transaction Log (_delta_log/*.json)           │
│    → Generated by: every Delta write + OPTIMIZE                     │
├─────────────────────────────────────────────────────────────────────┤
│  Level 2: TABLE-LEVEL STATS                                         │
│    → total row count, total byte size of the table                  │
│    → Stored in: Hive Metastore / Unity Catalog                      │
│    → Generated by: ANALYZE TABLE ... COMPUTE STATISTICS             │
├─────────────────────────────────────────────────────────────────────┤
│  Level 3: COLUMN-LEVEL STATS                                        │
│    → distinct count, min, max, null count, avg/max length, histogram│
│    → Stored in: Hive Metastore / Unity Catalog                      │
│    → Generated by: ANALYZE TABLE ... FOR COLUMNS ...                │
└─────────────────────────────────────────────────────────────────────┘
```

---

# PART 1: FILE-LEVEL STATISTICS

## 1.1 What Are They?

For each Parquet file in a Delta table, Delta automatically tracks:

| Statistic | Description | Example |
|---|---|---|
| `numRecords` | Row count in this file | 125,000 |
| `minValues` | Minimum value per column | `{"order_date": "2025-01-01", "amount": 0.99}` |
| `maxValues` | Maximum value per column | `{"order_date": "2025-03-31", "amount": 9999.99}` |
| `nullCount` | Number of NULLs per column | `{"product_id": 1500, "amount": 0}` |

**Default:** Stats are collected for the **first 32 columns** of the schema.

---

## 1.2 How Are File-Level Stats Generated?

### Automatic — on every Delta write
Every time data is written to a Delta table (INSERT, MERGE, OPTIMIZE, streaming write), Spark computes these stats per output file and writes them into the Delta log entry.

```
spark.write / df.writeStream / MERGE / OPTIMIZE
  │
  ├─ Spark writes Parquet file → part-00001-abc.parquet
  │
  └─ Delta computes:
       numRecords   = count rows in this file
       minValues    = per-column MIN across all rows in this file
       maxValues    = per-column MAX across all rows in this file
       nullCount    = per-column NULL count in this file
       
       Writes this as JSON into the Delta log commit file
```

### Number of Indexed Columns (configurable)
```sql
-- Default: first 32 columns get stats
-- Increase for wide tables where filter columns are beyond col 32
ALTER TABLE orders SET TBLPROPERTIES (
  'delta.dataSkippingNumIndexedCols' = '64'
);

-- Disable stats collection entirely (only if write speed is critical)
ALTER TABLE orders SET TBLPROPERTIES (
  'delta.dataSkippingNumIndexedCols' = '0'
);
```

---

## 1.3 Where Are File-Level Stats Stored?

**Inside the Delta Transaction Log** — specifically inside `_delta_log/*.json` commit files.

```
Table path: /mnt/datalake/orders/
  _delta_log/
    00000000000000000000.json   ← commit 0 (CREATE TABLE)
    00000000000000000001.json   ← commit 1 (INSERT)
    00000000000000000002.json   ← commit 2 (OPTIMIZE)
    00000000000000000010.checkpoint.parquet  ← checkpoint (compacted log)
  part-00001-abc123.parquet
  part-00002-def456.parquet
```

Each `*.json` commit file contains `add` actions with an embedded `stats` field:

```json
{
  "add": {
    "path": "part-00001-abc123.parquet",
    "size": 134217728,
    "modificationTime": 1716825600000,
    "dataChange": true,
    "stats": "{
      \"numRecords\": 125000,
      \"minValues\": {
        \"order_id\": 1,
        \"customer_id\": \"CUST_0001\",
        \"order_date\": \"2025-01-01\",
        \"amount\": 0.99
      },
      \"maxValues\": {
        \"order_id\": 125000,
        \"customer_id\": \"CUST_9999\",
        \"order_date\": \"2025-03-31\",
        \"amount\": 9999.99
      },
      \"nullCount\": {
        \"order_id\": 0,
        \"customer_id\": 0,
        \"order_date\": 0,
        \"amount\": 12
      }
    }"
  }
}
```

## 1.4 How to VIEW File-Level Stats

### Method 1: Query the Delta Log Directly (JSON)
```python
# Read the raw Delta log JSON files
import json

log_path = "/mnt/datalake/orders/_delta_log/00000000000000000001.json"

with open(log_path) as f:
    for line in f:
        entry = json.loads(line)
        if "add" in entry and entry["add"].get("stats"):
            stats = json.loads(entry["add"]["stats"])
            print(f"File: {entry['add']['path']}")
            print(f"  numRecords : {stats['numRecords']}")
            print(f"  minValues  : {stats['minValues']}")
            print(f"  maxValues  : {stats['maxValues']}")
            print(f"  nullCount  : {stats['nullCount']}")
            print()
```

### Method 2: Using the Delta Log as a Spark Table
```python
# Read the Delta log as a structured Spark DataFrame
from delta.tables import DeltaTable

dt = DeltaTable.forName(spark, "orders")
log_df = spark.read.json("/mnt/datalake/orders/_delta_log/*.json")

# Extract file-level stats from the 'add' column
from pyspark.sql import functions as F

file_stats = (
    log_df
    .filter(F.col("add").isNotNull())
    .select(
        F.col("add.path").alias("file_path"),
        F.col("add.size").alias("file_size_bytes"),
        F.get_json_object("add.stats", "$.numRecords").cast("long").alias("num_records"),
        F.get_json_object("add.stats", "$.minValues.order_date").alias("min_order_date"),
        F.get_json_object("add.stats", "$.maxValues.order_date").alias("max_order_date"),
        F.get_json_object("add.stats", "$.nullCount.amount").cast("long").alias("null_amount_count")
    )
)
file_stats.show(truncate=False)
```

**Output:**
```
+----------------------+-----------------+-----------+--------------+--------------+------------------+
|file_path             |file_size_bytes  |num_records|min_order_date|max_order_date|null_amount_count |
+----------------------+-----------------+-----------+--------------+--------------+------------------+
|part-00001-abc123...  |134217728        |125000     |2025-01-01    |2025-03-31    |12                |
|part-00002-def456...  |89478485         |89000      |2025-04-01    |2025-06-30    |0                 |
+----------------------+-----------------+-----------+--------------+--------------+------------------+
```

```sql

```


# PART 2: TABLE-LEVEL STATISTICS

## 2.1 What Are They?

| Statistic | Description | Example |
|---|---|---|
| `rowCount` | Total number of rows in the table | 50,000,000 |
| `sizeInBytes` | Total physical size of all data files | 10,737,418,240 (10 GB) |

Used by Catalyst to decide: join strategy (BHJ vs SMJ), memory allocation, partition count estimation.

---

## 2.2 How Are Table-Level Stats Generated?

**NOT automatic** — you must run `ANALYZE TABLE` explicitly.

```sql
ANALYZE TABLE orders COMPUTE STATISTICS;
```

What happens internally:
```
1. Spark scans all active files listed in the Delta log
2. Counts total rows  → rowCount
3. Sums file sizes    → sizeInBytes
4. Writes both values into the Hive Metastore (or Unity Catalog)
```

> Note: For Delta tables, `sizeInBytes` can also be read from `DESCRIBE DETAIL` without ANALYZE. But `rowCount` in the metastore is only updated by ANALYZE.

---

## 2.3 Where Are Table-Level Stats Stored?

**Hive Metastore** (external metadata database — usually MySQL or embedded Derby for local):
- Database: `metastore_db` (default embedded) or external MySQL/PostgreSQL
- Table: `TABLE_PARAMS`
- Key entries: `spark.sql.statistics.numRows`, `spark.sql.statistics.totalSize`

**Unity Catalog** (Databricks managed):
- Stored in Databricks-managed catalog service
- Accessible via `information_schema.tables`

```
Metastore internal storage (conceptual):
  TABLE_PARAMS table:
    TBL_ID   | PARAM_KEY                            | PARAM_VALUE
    ─────────────────────────────────────────────────────────────
    42       | spark.sql.statistics.numRows         | 50000000
    42       | spark.sql.statistics.totalSize       | 10737418240
```

# PART 3: COLUMN-LEVEL STATISTICS

## 3.1 What Are They?

Per-column metadata collected across the **entire table** (not per file):

| Statistic | Description | Example |
|---|---|---|
| `distinctCount` | Approximate number of unique values | 150,000 |
| `min` | Minimum value in the column | `2025-01-01` |
| `max` | Maximum value in the column | `2026-05-27` |
| `nullCount` | Total NULLs in the table | 4,500 |
| `avgLen` | Average byte length (strings) | 12 |
| `maxLen` | Maximum byte length (strings) | 64 |
| `histogram` | Value frequency distribution (optional) | equi-height histogram |

---

## 3.2 How Are Column-Level Stats Generated?

Run `ANALYZE TABLE ... FOR COLUMNS`:

```sql
-- Specific columns (recommended — cheaper than ALL COLUMNS)
ANALYZE TABLE orders COMPUTE STATISTICS FOR COLUMNS customer_id, order_date, amount;

-- All columns (expensive for wide tables)
ANALYZE TABLE orders COMPUTE STATISTICS FOR ALL COLUMNS;

-- With histogram (value distribution — needed for skew detection)
ANALYZE TABLE orders COMPUTE STATISTICS
FOR COLUMNS customer_id, amount
WITH HISTOGRAMS;
```

What happens internally:
```
Spark runs a full table scan:
  SELECT
    COUNT(*)                        AS rowCount,
    COUNT(DISTINCT customer_id)     AS distinctCount_customer_id,
    MIN(customer_id)                AS min_customer_id,
    MAX(customer_id)                AS max_customer_id,
    SUM(CASE WHEN customer_id IS NULL THEN 1 ELSE 0 END) AS nullCount_customer_id,
    AVG(LENGTH(customer_id))        AS avgLen_customer_id,
    MAX(LENGTH(customer_id))        AS maxLen_customer_id,
    ...  (same for each requested column)
  FROM orders

Results written to Hive Metastore / Unity Catalog
```

> This is a **full table scan** — it can be expensive on large tables. Run selectively.

---

## 3.3 Where Are Column-Level Stats Stored?

**Hive Metastore** — `COLUMN_STATS_AGGR` table and `TABLE_PARAMS`:

```
COLUMN_STATS_AGGR (conceptual):
  DB_NAME | TABLE_NAME | COL_NAME    | NUM_NULLS | NUM_DISTINCTS | LOW_VALUE | HIGH_VALUE | AVG_COL_LEN | MAX_COL_LEN
  ────────────────────────────────────────────────────────────────────────────────────────────────────────────────
  mydb    | orders     | customer_id | 0         | 150000        | CUST_0001 | CUST_99999 | 10          | 12
  mydb    | orders     | order_date  | 0         | 517           | 2025-01-01| 2026-05-27 | NULL        | NULL
  mydb    | orders     | amount      | 12        | 82000         | 0.99      | 9999.99    | NULL        | NULL
```

**Unity Catalog** (Databricks managed):
- Accessible via `information_schema.column_statistics`

# PART 4: SIDE-BY-SIDE COMPARISON

| Property | File-Level Stats | Table-Level Stats | Column-Level Stats |
|---|---|---|---|
| **Granularity** | Per Parquet file | Entire table | Per column across table |
| **Generated by** | Auto on every write | `ANALYZE TABLE` | `ANALYZE TABLE FOR COLUMNS` |
| **Stored in** | Delta log JSON | Hive Metastore / UC | Hive Metastore / UC |
| **Format** | JSON inside `_delta_log/` | Key-value in metastore | Key-value in metastore |
| **Auto-refreshed** | YES (on every Delta write) | NO (must re-ANALYZE) | NO (must re-ANALYZE) |
| **Used for** | Data skipping (file pruning) | Join strategy selection | Cardinality, skew detection |
| **Stale risk** | No (auto-updated) | YES (after writes) | YES (after writes) |
| **How to view** | Query `_delta_log/*.json` | `DESCRIBE EXTENDED` | `DESCRIBE EXTENDED col_name` |
| **Delta only?** | YES | NO (all formats) | NO (all formats) |

# PART 5: COMPLETE VIEWING CHEAT SHEET

```sql
-- ─────────────────────────────────────────────────────────────────
-- FILE-LEVEL STATS (Delta Log)
-- ─────────────────────────────────────────────────────────────────

-- 1. Summary: number of files and total size
DESCRIBE DETAIL my_table;

-- 2. Per-file stats via log (PySpark)
-- spark.read.json("/path/to/_delta_log/*.json")
-- .filter(col("add").isNotNull())
-- .select("add.path", "add.size", "add.stats")

-- 3. Commit history (per-operation metrics)
DESCRIBE HISTORY my_table;


-- ─────────────────────────────────────────────────────────────────
-- TABLE-LEVEL STATS (Metastore / UC)
-- ─────────────────────────────────────────────────────────────────

-- Generate
ANALYZE TABLE my_table COMPUTE STATISTICS;

-- View (look for "Statistics" row at bottom of output)
DESCRIBE EXTENDED my_table;

-- View via UC information_schema
SELECT table_name, row_count, bytes
FROM information_schema.tables
WHERE table_schema = 'my_schema' AND table_name = 'my_table';


-- ─────────────────────────────────────────────────────────────────
-- COLUMN-LEVEL STATS (Metastore / UC)
-- ─────────────────────────────────────────────────────────────────

-- Generate (specific columns)
ANALYZE TABLE my_table COMPUTE STATISTICS FOR COLUMNS col1, col2;

-- Generate with histogram
ANALYZE TABLE my_table COMPUTE STATISTICS FOR COLUMNS col1 WITH HISTOGRAMS;

-- View a specific column's stats
DESCRIBE EXTENDED my_table col1;

-- View all columns via UC information_schema
SELECT column_name, distinct_count, null_count, min, max
FROM information_schema.column_statistics
WHERE table_schema = 'my_schema' AND table_name = 'my_table';


-- ─────────────────────────────────────────────────────────────────
-- VERIFY DATA SKIPPING IS USING STATS
-- ─────────────────────────────────────────────────────────────────

-- Check physical plan for file pruning metrics
EXPLAIN COST SELECT * FROM my_table WHERE col1 = 'value';
-- Look for: "PartitionFilters", "PushedFilters", numFiles count

-- After running query: check Spark UI
-- SQL tab → Query Details → "number of files read" vs "number of files skipped"
```

# PART 6: STAT STALENESS & REFRESH STRATEGY

```
Timeline example:

  DAY 1:  Table created, 10M rows loaded
           ANALYZE TABLE → rowCount=10M, col stats accurate ✓

  DAY 2:  5M more rows appended
           File-level stats: auto-updated for NEW files ✓
           Table-level stats: still shows 10M (stale!) ✗
           Column stats: still reflect DAY 1 data only (stale!) ✗

  DAY 3:  OPTIMIZE runs
           File-level stats: refreshed for rewritten files ✓
           Table/column stats: STILL stale — OPTIMIZE does NOT update metastore ✗

  FIX:    Run ANALYZE after every significant data change
           OR rely on AQE for runtime correction
```

### Recommended Refresh Schedule
```python
# Nightly maintenance pattern
def refresh_stats(table_name, key_columns):
    # Step 1: Compact files (refreshes file-level stats automatically)
    spark.sql(f"OPTIMIZE {table_name}")
    
    # Step 2: Refresh metastore stats
    cols = ", ".join(key_columns)
    spark.sql(f"""
        ANALYZE TABLE {table_name}
        COMPUTE STATISTICS FOR COLUMNS {cols}
    """)
    print(f"Stats refreshed for {table_name}")

# Run nightly for critical tables
refresh_stats("orders", ["customer_id", "order_date", "region", "amount"])
```
